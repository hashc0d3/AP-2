# Настройки

Настройки разделены на два файла, и это разделение сознательное:

| Файл          | Что в нём                       | Кто правит         |
| ------------- | ------------------------------- | ------------------ |
| `.env`        | секреты и параметры окружения   | администратор      |
| `config.toml` | поведение парсера               | владелец мониторинга |

Ни один из них в git не попадает. Рядом лежат `.env.example` и
`config.toml.example` — их и нужно копировать при установке.

Все ключи `config.toml` необязательные: значения по умолчанию заданы в
классе `Settings` (`avito_monitor/config.py`) и являются единственным
источником правды. Незнакомый ключ не роняет запуск — он попадает в лог с
пометкой «пропущен», поэтому опечатку видно сразу, но сервер встаёт.

Секрет, случайно оказавшийся в `config.toml`, игнорируется с
предупреждением: `PROXY_STRING`, `PROXY_CHANGE_URL`, `PROXY_STRING_2`,
`PROXY_CHANGE_URL_2`, `PROXY_STRING_3`, `PROXY_CHANGE_URL_3` и
`COOKIES_API_KEY` читаются только из окружения.

## .env

### Обязательные

| Переменная         | Пример                                    | Зачем                                       |
| ------------------ | ----------------------------------------- | ------------------------------------------- |
| `PROXY_STRING`     | `user:pass@mproxy.site:20085`             | мобильный прокси, через него идут запросы   |
| `PROXY_CHANGE_URL` | `https://aproxy.site/?proxy_key=…`        | ссылка смены IP у оператора прокси          |
| `COOKIES_API_KEY`  | `sk_live_…`                               | ключ сервиса cookies (покупка, разблокировка) |
| `APP_LOGIN`        | `admin`                                   | логин входа в интерфейс                     |
| `APP_PASSWORD`     | —                                         | пароль входа                                |

Пароль по умолчанию (`change_me`) нужно сменить: приложение предупреждает об
этом при каждом запуске.

### Второй и третий прокси

Необязательно, но заметно ускоряет опрос. Наборы cookies делятся между
каналами поровну, поэтому на каждый IP приходится меньше запросов и
он реже ловит `429`. Забаненный канал меняет адрес в фоне, а его наборы на
это время уходят к соседу — опрос не останавливается.

| Переменная           | Пример                                    | Зачем                                       |
| -------------------- | ----------------------------------------- | ------------------------------------------- |
| `PROXY_STRING_2`     | `user:pass@mproxy.site:10341`             | второй мобильный прокси                     |
| `PROXY_CHANGE_URL_2` | `https://aproxy.site/?proxy_key=…`        | смена IP второго прокси                     |
| `PROXY_STRING_3`     | `user:pass@mproxy.site:26101`             | третий мобильный прокси                     |
| `PROXY_CHANGE_URL_3` | `https://aproxy.site/?proxy_key=…`        | смена IP третьего прокси                    |

### Сервер

| Переменная         | По умолчанию | Описание                                                        |
| ------------------ | ------------ | --------------------------------------------------------------- |
| `WEB_PORT`         | `8765`       | порт интерфейса; важнее значения `web_port` из `config.toml`     |
| `WEB_HOST`         | `127.0.0.1`  | адрес прослушивания; в Docker `0.0.0.0`                          |
| `WEB_OPEN_BROWSER` | `1`          | открывать браузер при старте; в контейнере `0`                   |
| `ALLOWED_HOST`     | не задан     | обслуживать только этот домен (см. ниже)                         |
| `SESSION_TTL_DAYS` | `30`         | сколько дней живёт сессия браузера                               |
| `SKIP_VPN_BYPASS`  | не задан     | `1` — не править таблицу маршрутов; только Windows               |

`ALLOWED_HOST` закрывает обращение к интерфейсу по IP в обход nginx и TLS.
Локальные адреса разрешены всегда — по ним ходит healthcheck контейнера.

### Push-уведомления

| Переменная           | Описание                                                    |
| -------------------- | ----------------------------------------------------------- |
| `VAPID_PRIVATE_KEY`  | приватный ключ VAPID, если не хранить его файлом            |
| `VAPID_PUBLIC_KEY`   | публичный ключ VAPID                                        |
| `VAPID_CONTACT`      | контакт для push-сервиса, например `mailto:admin@site.ru`   |

Ключи создаются командой `python -m avito_monitor.tools.generate_vapid` и по
умолчанию сохраняются в `storage/`. Переменные нужны, только если ключи
должны приходить из окружения (например, из секретов CI).

## config.toml

Все ключи — в секции `[avito]`.

### Что показывать

| Ключ                 | По умолчанию                | Описание                                                                 |
| -------------------- | --------------------------- | ------------------------------------------------------------------------ |
| `ignore_promotion`   | `true`                      | скрывать платно продвинутые; если бейдж на всех карточках JSON — не прячем |
| `private_only`       | `false`                     | если `true` — прятать `/brands/` и `/company/` в ленте                   |
| `seller_skip`        | `[]`                        | чёрный список продавцов — подстроки в имени или ссылке на профиль        |
| `title_must_contain` | `[]`                        | название должно содержать хотя бы одно слово из списка                   |
| `title_skip`         | `["книга", "чехол", …]`     | название не должно содержать ни одного слова из списка                   |

Сравнение в `seller_skip` идёт без учёта регистра, пробелов и знаков,
поэтому `премиум` поймает и `П Р Е М И У М . Store`. Список из `config.toml`
действует всегда, а чёрный список из интерфейса добавляется к нему.

Веб-ссылка идёт с ``s=104`` и ``owner[]=private``. JSON API — как 6 сентября:
``presentationType=serp``, ``sort=date``, ``owner[0]=private``. В ленту —
карточки без платного продвижения. Первый цикл кладёт текущую выдачу.
Дальше туда попадает любой новый ID.

Ключи `max_age` и `notify_max_age` больше ни на что не влияют.

### Модели iPhone

| Ключ               | По умолчанию | Описание                                             |
| ------------------ | ------------ | ---------------------------------------------------- |
| `iphone_min_model` | `0`          | нижняя граница поколения по названию; `0` — без границы |
| `iphone_max_model` | `0`          | верхняя граница поколения                            |
| `iphone_models`    | не задан     | список конкретных моделей; не задан — фильтр выключен |

Идентификаторы моделей — `"13"`, `"13-pro"`, `"16-e"`, `"17-air"` (полный
список виден в интерфейсе). Одно число означает линейку целиком: `[13]`
разворачивается во все варианты 13-й, а `["13"]` — только базовая модель.

Обычно модели задаются в интерфейсе: оттуда фильтр уходит прямо в ссылку
Avito, то есть отсев происходит на стороне Avito и работает точнее, чем
разбор названия.

### Страницы выдачи

| Ключ                  | По умолчанию | Описание                                        |
| --------------------- | ------------ | ----------------------------------------------- |
| `pages`               | `2`          | пока не используется: цикл делает один запрос   |
| `pause_between_pages` | `0`          | пока не используется                            |

Пагинацию ``p=1`` / ``p=2`` временно отключили: парсер берёт JSON как есть.

### Темп опроса

| Ключ                  | По умолчанию | Минимум | Описание                                          |
| --------------------- | ------------ | ------- | ------------------------------------------------- |
| `poll_interval`       | `3`          | `1`     | нижняя граница интервала между циклами, секунды   |
| `poll_interval_max`   | `24`         | —       | верхняя граница: до неё замедляемся при отказах   |
| `per_cookie_interval` | `12`         | `3`     | один набор cookies не бьёт Avito чаще, чем раз в столько секунд |
| `retry_pause`         | `12`         | `3`     | пауза после срыва сети; после 429/439 не ждём     |
| `request_timeout`     | `12`         | `3`     | общее время запроса; соединение из них 5 с, максимум 12 |
| `ip_change_wait`      | `25`         | `1`     | сколько ждать подъёма туннеля после смены IP      |

Интервал плавает между `poll_interval` и `poll_interval_max`: серия отказов
Avito замедляет опрос, серия чистых циклов — ускоряет. Фактический интервал
не бывает чаще, чем `per_cookie_interval / размер пула`, — иначе один и тот
же набор cookies начал бы бить Avito слишком часто и быстро сгорел.

Считайте нагрузку на один IP, а не на парсер: циклы разложены по каналам,
поэтому при трёх прокси каждый адрес получает запрос раз в
`poll_interval × 3` секунд. Это и позволяет опрашивать чаще, чем с одним
каналом, не приближаясь к лимиту.

`request_timeout` — всё время запроса, не больше 12 с. Из них соединение
с прокси рвётся через 5 с, остаток уходит на тело JSON. curl складывает
части кортежа, поэтому 20 с «на тело» поверх 5 с соединения давали 25 с
простоя на медленном канале.

Значения приводятся к границам при загрузке: занизить их ниже минимума
нельзя, `request_timeout` выше 12 с обрезается.

Старое имя `pause_general` продолжает работать как `retry_pause`. Ключи
`url`, `api_url`, `pause_max`, `socks5_proxy`, `max_age` и `notify_max_age`
больше ни на что не влияют и молча игнорируются.

### Пул cookies

| Ключ                   | По умолчанию | Минимум | Описание                                    |
| ---------------------- | ------------ | ------- | ------------------------------------------- |
| `cookie_pool_size`     | `16`         | `1`     | сколько наборов держать наготове            |
| `cookie_unblock_pause` | `60`         | `30`    | пауза между обходами пула, секунды          |

Больше наборов — чаще опрос, но выше расход средств на сервисе cookies.

| Ключ       | По умолчанию | Описание                                            |
| ---------- | ------------ | --------------------------------------------------- |
| `web_port` | `8765`       | порт; переменная `WEB_PORT` важнее этого значения   |

## Проверка настроек

Загрузку конфига покрывают тесты `tests/test_config.py`: приведение типов,
границы значений, алиасы старых ключей, поведение при мусоре в файле.
Быстро посмотреть, что приложение реально прочитало:

```bash
python -c "from avito_monitor.config import load_settings; print(load_settings())"
```
