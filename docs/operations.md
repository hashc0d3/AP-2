# Эксплуатация

## Ежедневная работа

Мониторинг не запускается сам после перезапуска приложения: цикл опроса
ждёт кнопку «Начать поиск» в интерфейсе. Это сделано специально — Avito
опрашивается только тогда, когда результат кому-то нужен, и cookies не
расходуются впустую.

Порядок такой: войти в интерфейс → выбрать регион, категорию и, при
необходимости, модели iPhone → «Начать поиск». Лента наполнится текущей
выдачей, дальше в неё попадают только новые объявления.

Остановка поиска не выключает приложение: веб-интерфейс и обслуживание пула
cookies продолжают работать.

## Логи

Файлы лежат в `logs/` (в Docker — том `parser-logs`). Ротация — каждые
500 КБ, старые файлы жмутся в zip и удаляются через сутки.

| Файл                    | Что внутри                                        |
| ----------------------- | ------------------------------------------------- |
| `parser.log`            | цикл опроса: сколько получено, сколько подошло, паузы |
| `cookies.log`           | сервис пула: покупки, разблокировки, ошибки сервиса |
| `cookie_lifecycle.log`  | история каждого набора cookies: когда куплен, когда сгорел |

```bash
docker compose logs -f --tail=100 monitor    # консоль приложения
docker compose exec monitor tail -f logs/parser.log
```

Нормальная строка цикла выглядит так:

```
Цикл на cookie id=17 [2/5]
Получено объявлений: 50
Подходящих: 2 (промо 31, старые 14, продавец 3)
Новых объявлений: 2, возраст 41–58 сек
Цикл 1.9 с, пауза 2.5 с, темп 4.0 с, наборов 5
```

`темп` — текущий интервал опроса. Если он держится у `poll_interval_max`,
значит Avito ограничивает запросы и парсер сознательно сбавил обороты.

## Пул cookies

Один набор cookies живёт около 12 часов и сгорает после серии отказов
Avito, поэтому наборы покупаются пулом и обслуживаются в фоне.

Посмотреть состояние пула:

```bash
docker compose exec monitor cat storage/pool.json
docker compose exec monitor ls storage/cookies/
```

Статусы набора: `ready` (свободен), `in_use` (в работе), `blocked` (ждёт
разблокировки), `dead` (старше 12 часов, удаляется).

Баланс сервиса видно в интерфейсе (меню пользователя) и через
`GET /api/resource/balance`. Если баланс кончился, пул перестаёт
пополняться: в `cookies.log` появятся ошибки покупки, а опрос продолжится
на остатках, пока они не сгорят.

Пул можно обслуживать отдельным процессом, не запуская мониторинг:

```bash
python -m avito_monitor.cookies.service
```

Два обслуживающих процесса одновременно не запустятся — PID-файл
`storage/cookies/service.pid` этого не позволит, иначе они выкупали бы
наборы сверх нужного количества.

## Мобильный прокси

Запросы к Avito идут только через мобильный прокси. IP меняется
автоматически, когда Avito отвечает отказом (`429`) или отдаёт антибот
вместо API. Проверить прокси и скорость смены IP:

```bash
python -m avito_monitor.tools.bench_speed --ipchange
python -m avito_monitor.tools.bench_speed --api 5
```

На Windows приложение при старте прописывает маршрут до прокси в обход VPN.
Если это мешает, поставьте `SKIP_VPN_BYPASS=1`; в Docker и на Linux
переменная не нужна.

## Диагностика по логам

Разбор накопленного лога без обращения к сети:

```bash
python -m avito_monitor.tools.bench_speed --log logs/parser.log
```

Отчёт покажет период цикла, длительность запроса, долю сбоев и возраст
объявлений в момент попадания в ленту — по нему видно, успевает ли парсер
за выдачей.

## Типичные ситуации

**Лента не обновляется, хотя поиск запущен.** Проверьте `parser.log`: если
там `429` и смена IP каждый цикл — прокси под лимитом Avito, стоит
увеличить `poll_interval` или добавить наборов в пул. Если в логе всё чисто,
проблема на стороне браузера: поток `/events` мог оборваться о буферизующий
прокси, проверьте `proxy_buffering off` в nginx.

**«Нет готового cookie».** Пул пуст: либо кончился баланс сервиса, либо все
наборы сгорели одновременно. Смотрите `cookies.log`.

**Каждый вход требует пароль заново.** Cookie сессии не доходит до
браузера — так бывает, если сайт открыт по HTTP на нелокальном адресе.
Нужен HTTPS через nginx.

**«Позвонить» отвечает «Avito не подключён».** Привязанная сессия Avito
истекла. Меню → «Привязка Avito» → импортировать cookies заново.

**Push не приходят.** Проверьте `GET /api/push/vapid`: если
`configured: false`, ключи не созданы (см.
[deployment.md](deployment.md#5-push-уведомления)). На iPhone сайт должен
быть добавлен «На экран Домой», иначе push приходят только при открытой
вкладке.

**Приложение не стартует: «Не найден config.toml».** Скопируйте
`config.toml.example` в `config.toml`. В Docker файл монтируется с хоста.

**Предупреждение о пароле по умолчанию в логе.** `APP_PASSWORD` всё ещё
`change_me` — смените его в `.env` и перезапустите контейнер.

## Сброс состояния

| Что сбросить            | Как                                                          |
| ----------------------- | ------------------------------------------------------------ |
| лента объявлений        | кнопка очистки в интерфейсе или `POST /api/reset`             |
| память о показанном     | удалить `storage/seen.json` (сбрасывается и при старте поиска)|
| все сессии входа        | удалить `storage/app_sessions.json`                           |
| привязку Avito          | меню → «Привязка Avito» → отключить                           |
| пул cookies             | удалить `storage/cookies/` и `storage/pool.json` (наборы будут выкуплены заново) |

После правки файлов в `storage/` контейнер нужно перезапустить:

```bash
docker compose restart monitor
```
