# Разработка

## Окружение

Нужны Python 3.11+ и Node.js 20+.

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # Linux/macOS
pip install -r requirements.txt
pip install pytest ruff playwright
python -m playwright install chromium

cd web && npm ci && cd ..
```

Настройки нужны и для разработки: скопируйте `config.toml.example` в
`config.toml`. Секреты для тестов не требуются — тесты не выходят в сеть.

## Запуск

```bash
python -m avito_monitor            # приложение целиком
cd web && npm run dev              # интерфейс с горячей перезагрузкой
```

`npm run dev` поднимает Vite на своём порту и проксирует API на `8765`,
поэтому приложение должно быть запущено параллельно.

Сервер раздаёт `static/`, то есть собранную версию. После правок интерфейса
нужен `npm run build` — иначе на `8765` останется старая сборка.

## Проверки

```bash
python -m pytest                   # все тесты
python -m ruff check .             # линтер
python -m ruff format .            # форматирование
cd web && npm run check            # типы + eslint + prettier
```

`npm run check` — это `typecheck`, `lint` и `format:check` подряд;
`npm run lint:fix` и `npm run format` правят то, что можно исправить
автоматически.

Перед сдачей работы должны проходить все четыре команды.

## Тесты

Тесты лежат в `tests/`, запускаются `pytest` без аргументов (пути и опции
заданы в `pyproject.toml`).

| Файл                  | Что проверяет                                          |
| --------------------- | ------------------------------------------------------ |
| `test_config.py`      | загрузку настроек: типы, границы, алиасы, мусор в файле |
| `test_iphone.py`      | определение и нормализацию моделей iPhone               |
| `test_search_urls.py` | сборку ссылок поиска (web, API, фильтр моделей)         |
| `test_items.py`       | разбор ответа Avito                                     |
| `test_filters.py`     | отсев объявлений: название, возраст, продавец, модели   |
| `test_cookie_ring.py` | ротацию наборов cookies и переиспользование клиентов    |
| `test_pacer.py`       | адаптивный темп опроса                                  |
| `test_auth.py`        | вход, сессии, срок жизни токена                         |
| `test_feed.py`        | ленту: добавление, очистку, сохранение, подписки SSE    |
| `test_web_api.py`     | HTTP-API на живом сервере                               |
| `test_data.py`        | целостность справочников и совпадение копий с фронтендом |
| `test_ui_smoke.py`    | интерфейс в headless-браузере (Playwright)              |

### Изоляция

`tests/conftest.py` держит тесты подальше от реальных данных, и это стоит
понимать до написания новых:

- `isolated_storage` (автоматическая) переводит все файлы приложения во
  временный каталог. Модули запоминают пути в своих глобальных переменных
  при импорте, поэтому подменять `avito_monitor.paths` недостаточно — нужно
  переопределить константу в каждом модуле, который её использует. Добавили
  новый файл в `storage/`? Допишите его в `_PATCHED_PATHS`.
- `fresh_search_session` и `fresh_feed` (автоматические) дают каждому тесту
  собственные `SESSION` и `FEED` вместо синглтонов процесса.
- `offline` (автоматическая) запрещает обращения к `spfa.pro`: поход в сеть
  должен быть заметной ошибкой, а не тихой задержкой.
- `settings`, `credentials`, `storage_dir`, `cookies_dir` — готовые данные
  для тестов.

### UI-тесты

`test_ui_smoke.py` открывает собранный интерфейс в Chromium поверх реального
сервера. Тесты специально поверхностные: они не проверяют вид страницы, а
ловят то, что не видно ни типам, ни линтеру — пропавший `id` в разметке,
исключение при сборке экрана, неработающий вход.

Тесты пропускаются, если не установлен Playwright, не скачан браузер или не
собран `static/` — это не должно мешать остальным проверкам. Значит, после
правок интерфейса сначала `npm run build`, потом `pytest`.

Две вещи, о которые легко споткнуться при написании новых UI-тестов:

- форма поиска живёт в выдвижной панели, закрытой при старте, — её нужно
  открыть (`#filters-open-btn`), а списки категорий и моделей ещё и раскрыть
  (`#category-trigger`, `#iphone-models-trigger`);
- после входа страница держит открытым поток `/events`, поэтому ждать
  `networkidle` бессмысленно — «тишины в сети» не наступит.

## Структура кода

### Backend

Пакет `avito_monitor` разложен по слоям: чем ниже в таблице, тем меньше
модуль знает об остальных (подробнее — [architecture.md](architecture.md)).

| Слой              | Модули                                              |
| ----------------- | --------------------------------------------------- |
| точка входа       | `__main__`, `monitor/loop`                          |
| веб               | `web/*`                                             |
| предметная логика | `avito/*`, `cookies/*`, `monitor/{pacer,seen}`      |
| инфраструктура    | `net/*`, `spfa`, `config`, `paths`, `logging_setup`  |

Правила, которые стоит соблюдать:

- Пути к файлам — только через `avito_monitor.paths`. Ни одного
  `Path("storage/…")` в коде: иначе запуск из другого каталога создаст
  данные не там, где их ждёт Docker-том.
- Настройки — только через `Settings`. Значения по умолчанию живут в
  датаклассе и нигде больше; `config.toml` их лишь переопределяет.
- Обращения к `spfa.pro` — только через `spfa.py`.
- Внешние ошибки переводятся в HTTP-коды один раз, в `routes.dispatch()`.
  Обработчику достаточно бросить `ValueError` — это станет `400`.

### Добавить эндпоинт

1. Написать функцию `_имя(request: Request) -> Response` в `web/routes.py`.
2. Добавить строку в `ROUTES`. По умолчанию эндпоинт закрыт;
   `requires_auth=False` ставится осознанно и только для того, что не
   содержит секретов.
3. Добавить метод в `web/src/api.ts` и, если нужно, тип в `web/src/types.ts`.
4. Дописать тест в `tests/test_web_api.py` и раздел в
   [api.md](api.md).

### Справочники

`avito_monitor/data/*.json` — регионы, категории, модели iPhone. Это часть
кода: без них не собрать ни одной ссылки, поэтому они лежат внутри пакета и
объявлены в `[tool.setuptools.package-data]`.

Интерфейс держит свои копии (`web/src/iphone-models.ts`,
`web/src/region-timezones.ts`), чтобы не ждать ответа сервера при
отрисовке. Источником правды считается backend; расхождение ловит
`tests/test_data.py`. Правите справочник — правьте обе копии и запускайте
тесты.

### Frontend

`web/src/` — vanilla TypeScript без фреймворка, сборка Vite, стили
Tailwind 4 плюс `styles.css`.

| Модуль                | Ответственность                                  |
| --------------------- | ------------------------------------------------ |
| `main.ts`             | точка входа, экран входа, переключение экранов     |
| `monitor.ts`          | форма поиска и её состояние                       |
| `api.ts`              | все обращения к серверу (с таймаутами)            |
| `types.ts`            | типы ответов сервера                              |
| `dom.ts`              | обёртки над `getElementById`, выпадающие панели    |
| `ad-card.ts`          | разметка карточки объявления                       |
| `ad-feed.ts`          | лента: поток SSE, добавление, пустое состояние     |
| `avito-session.ts`    | привязка сессии Avito                              |
| `saved-urls*.ts`      | сохранённые ссылки поиска                          |
| `search-settings.ts`  | запоминание условий поиска в браузере              |
| `user-menu.ts`        | меню пользователя, баланс, push                    |
| `push-notify.ts`      | подписка на Web Push и service worker              |
| `parse.ts`            | `asText` — безопасное приведение к строке          |

Данные из сети и `localStorage` считаются недоверенными: приводите их
`asText` из `parse.ts`, а не `String()` — иначе в интерфейс попадёт
`[object Object]`.

Включены строгие проверки TypeScript, в том числе
`noUncheckedIndexedAccess`: обращение по индексу даёт `T | undefined`, и это
нужно обрабатывать (`?? ""`), а не подавлять.

ESLint настроен на `no-floating-promises` и `no-misused-promises`. Если
промис игнорируется намеренно (например, в обработчике события),
пометьте это словом `void`: `onclick = () => void save()`.

## Стиль

- Ruff: длина строки 100, форматирование `ruff format`. Настройки — в
  `pyproject.toml`.
- Prettier для `web/src`, ESLint с `typescript-eslint`.
- Комментарии и докстринги на русском — это язык проекта. Докстринг
  объясняет назначение и неочевидные решения («почему»), а не пересказывает
  код («что»).
- Русский текст в строках Ruff не считает опечаткой (правила `RUF001–003`
  отключены осознанно).

## Сборка пакета

Проект оформлен как устанавливаемый пакет:

```bash
pip install -e .
avito-monitor            # то же, что python -m avito_monitor
```

Это удобно для запуска из любого каталога, но обязательным не является.
