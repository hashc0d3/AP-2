# Архитектура

## Общая картина

Приложение — один процесс Python. `python -m avito_monitor` вызывает
`avito_monitor.monitor.loop.main()`, который поднимает всё остальное:

```
                    ┌─────────────────────────────┐
   браузер ────────▶│  web/server.py              │
   (static/ + API)  │  ThreadingHTTPServer        │
                    │  поток на каждый запрос     │
                    └──────────────┬──────────────┘
                                   │ читает/меняет
                                   ▼
                    ┌─────────────────────────────┐
                    │  search_session.py          │
                    │  что искать и идёт ли поиск │
                    └──────────────┬──────────────┘
                                   │ ждёт команду «Начать поиск»
                                   ▼
                    ┌─────────────────────────────┐        ┌──────────────┐
                    │  monitor/loop.py            │───────▶│  Avito API   │
                    │  главный поток              │  через │  (мобильный) │
                    └──────────────┬──────────────┘  прокси└──────────────┘
                                   │ новые объявления
                                   ▼
                    ┌─────────────────────────────┐
                    │  web/feed.py                │
                    │  лента + SSE + push         │
                    └─────────────────────────────┘

                    ┌─────────────────────────────┐        ┌──────────────┐
                    │  cookies/service.py         │───────▶│  spfa.pro    │
                    │  фоновый поток              │        │  (cookies)   │
                    └─────────────────────────────┘        └──────────────┘
```

Потоки в процессе:

| Поток                          | Что делает                                            |
| ------------------------------ | ----------------------------------------------------- |
| главный                        | цикл мониторинга: опрос Avito, фильтрация, публикация |
| `cookie-service`               | обслуживание пула cookies раз в `cookie_unblock_pause`|
| поток HTTP-сервера + по запросу| веб-интерфейс и API                                   |

Общее состояние живёт в двух синглтонах: `search_session.SESSION` (условия
поиска) и `web.feed` (лента объявлений). Оба защищены `threading.Lock`, а
цикл мониторинга просыпается по `threading.Event` — поэтому кнопка «Начать
поиск» действует сразу, а не через паузу опроса.

## Один цикл мониторинга

`monitor/loop.py`:

1. `CookieRing.next()` — взять следующий набор cookies и готовый HTTP-клиент.
2. `net/client.fetch_page()` — запросить страницы выдачи отдельными
   запросами подряд (`p=1`, затем сразу `p=2`). Первая страница часто
   забита магазинами, частные карточки уезжают на вторую.
3. Разобрать ответ Avito:
   - `429` — бан по IP: сразу уйти на соседний прокси и повторить запрос;
     на заблокированном меняем IP в фоне. Если канал один или сосед тоже
     под лимитом — отдать цикл;
   - `403`/`439` — набор cookies сгорел: пометить и взять другой, IP не менять;
   - `200` без JSON — вместо API отдали антибот: переключиться и повторить.
4. `avito/items.extract_items()` — вытащить объявления из JSON.
5. `avito/filters.select_new_ads()` — первый цикл кладёт текущую выдачу
   в ленту; дальше любой новый ID. Запрос к Avito — «по дате» и только
   частные (`s=104`, `owner[]=private`). Наши фильтры компаний и промо
   временно выключены.
6. `web/feed.publish_ads()` — отдать новое в ленту: она рассылает SSE
   открытым вкладкам и отправляет push.
7. `monitor/pacer.py` — выдержать паузу: при отказах Avito темп замедляется
   до `poll_interval_max`, при успехах возвращается к `poll_interval`.

Ошибка внутри цикла не останавливает мониторинг: она логируется, соединения
сбрасываются, следующий цикл начинается заново.

## Пул cookies

Avito отдаёт мобильный API только с валидными cookies, а набор живёт около
12 часов и сгорает после серии отказов. Поэтому наборы держатся пулом.

- Каждый набор — отдельный файл `storage/cookies/<id>.json`. Отдельные файлы
  нужны, чтобы цикл опроса и обслуживающий сервис писали одновременно, не
  затирая работу друг друга.
- Состояния набора: `ready` (свободен), `in_use` (в работе), `blocked` (ждёт
  разблокировки), `dead` (старше 12 часов, удаляется).
- `cookies/service.py` раз в `cookie_unblock_pause` секунд докупает наборы до
  `cookie_pool_size` и отправляет заблокированные на разблокировку.
  PID-файл `storage/cookies/service.pid` не даёт двум обслуживающим процессам
  выкупать наборы одновременно.
- `cookies/ring.py` выдаёт наборы по кругу и держит по HTTP-клиенту на набор:
  переиспользование соединения экономит время на TLS-хендшейке.

Все обращения к сервису cookies (`spfa.pro`) собраны в `spfa.py` — баланс,
покупка, разблокировка, конверсия ссылок.

## Мобильные прокси

`net/proxies.py` держит один или несколько каналов и раскладывает по ним
наборы cookies. Каналы работают параллельно: набор закреплён за своим
прокси, поэтому его соединение живёт между циклами, а каждый IP получает
лишь свою долю запросов и реже упирается в лимит Avito.

При `429`, обрыве туннеля или антиботе наборы забаненного канала
пересаживаются на свободный, а сам канал меняет IP в фоне (`net/proxy.py`).
Опрос при этом не останавливается — ждём новый адрес, только если свободных
каналов не осталось. Вернувшись, канал снова забирает свою долю наборов:
раскладка детерминированная, поэтому набор возвращается на прежний прокси и
переиспользует уже открытое соединение. Если прокси один — остаётся только
смена IP.

На Windows дополнительно прописывается маршрут до хостов оператора в обход
VPN (`SKIP_VPN_BYPASS=1` отключает это — в контейнере оно не нужно).

## Веб-интерфейс

`web/server.py` — `ThreadingHTTPServer`. Он сам обслуживает то, чему нужен
доступ к соединению:

- статику из `static/`;
- `GET /events` — поток SSE с новыми объявлениями;
- `GET /img?url=…` — прокси картинок: Avito отдаёт их только со своим
  `Referer`, из браузера напрямую они не загрузятся.

Всё остальное — таблица маршрутов в `web/routes.py`. Обработчик получает
`Request` и возвращает `Response`, не зная про сокеты и cookie. Проверка
входа и перевод исключений в коды ответа (`ValueError` → 400, `SpfaError` →
502, остальное → 500) сделаны один раз в `dispatch()`.

Вход — сессионные cookie: `auth.py` хранит только хэши токенов в
`storage/app_sessions.json`, пароль сравнивает за постоянное время, а токен
отдаёт браузеру с флагами `HttpOnly` и `SameSite`.

## Данные и справочники

`avito_monitor/data/*.json` — регионы (со часовыми поясами), категории и
модели iPhone. Это часть кода, а не пользовательские данные: без них не
собрать ни одной ссылки на поиск, поэтому они лежат внутри пакета и
объявлены в `package-data`.

Справочники дублируются в интерфейсе (`web/src/iphone-models.ts`,
`web/src/region-timezones.ts`), чтобы не ждать ответа сервера при отрисовке.
Расхождение между копиями ловят тесты в `tests/test_data.py` — источником
правды считается backend.

## Что где лежит

`storage/` (в Docker — том `parser-storage`):

| Файл                      | Что внутри                              |
| ------------------------- | --------------------------------------- |
| `cookies/<id>.json`       | наборы cookies пула                     |
| `pool.json`               | учёт пула: счётчик id, статусы          |
| `ads.json`                | лента объявлений (переживает перезапуск)|
| `seen.json`               | id уже показанных объявлений            |
| `app_sessions.json`       | хэши токенов входа                      |
| `avito_user.json`         | привязанная сессия Avito для «Позвонить»|
| `push_subscriptions.json` | подписки на push                        |
| `vapid_private.pem`       | ключи VAPID, если не заданы в `.env`    |
| `spfa_regions.json`       | кэш id локаций Avito                    |

`logs/` (том `parser-logs`): `parser.log`, `cookies.log`,
`cookie_lifecycle.log` — история покупок и блокировок наборов.

## Границы модулей

Правило простое: чем ниже в списке, тем меньше модуль знает об остальных.

| Слой              | Модули                                       | Знает о                     |
| ----------------- | -------------------------------------------- | --------------------------- |
| точка входа       | `__main__`, `monitor/loop`                   | обо всём                    |
| веб               | `web/*`                                      | о сессии поиска и Avito     |
| предметная логика | `avito/*`, `cookies/*`, `monitor/{pacer,seen}`| о конфиге и данных          |
| инфраструктура    | `net/*`, `spfa`, `config`, `paths`, `logging_setup` | ни о чём выше         |

Импорты внутрь цикла (`from … import` в теле функции) стоят там, где нужно
разорвать цикл зависимостей между `monitor/loop` и `web/feed`.
